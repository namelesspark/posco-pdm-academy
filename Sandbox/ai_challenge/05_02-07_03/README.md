## 실습 1. 생산 목표 도달 시뮬레이션

> while · break · continue · 무한루프 함정

### 상황

라인이 1시간마다 생산량을 기록함. 누적 생산량이 **목표치(800개)** 를 넘는 순간 즉시 멈추고,
몇 회차에 달성했는지 보고하는 게 목표.

단, 기록 중에 `0` 이나 **음수**(설비 정지·기록 오류)가 섞여 있음. 이건 집계에서 빼야 함.

> 데이터를 끝까지 다 써도 목표에 못 미칠 수 있음. 그 경우도 처리해야 함.

```python
production = [120, 0, 95, 130, -5, 110, 88, 0, 140, 102, 97, 115]
TARGET = 800
```

### 요구사항

1. `while` 로 리스트를 앞에서부터 훑기 (`for` 쓰지 말 것 — 이 문제는 `while` 연습)
2. 값이 `0` 이하면 `continue` 로 건너뛰되, **건너뛴 횟수**를 따로 셀 것
3. 정상 값이면 누적하고 `N회차: +값 (누적 X)` 형태로 출력
4. 누적이 `TARGET` 이상이 되는 순간 `break`
5. 반복이 끝난 뒤: 달성했으면 `목표 달성`, 못 했으면 `목표 미달` 출력
6. 마지막에 유효 횟수 / 건너뛴 횟수 출력

### 써야 하는 개념

`while` / `break` / `continue` / 인덱스 변수 갱신 / 누적변수 / 플래그 변수 / `len` / f-string

### 예상 출력

```
==============================================
      생산 목표 도달 시뮬레이션
==============================================
1회차: +120 (누적 120)
3회차: +95 (누적 215)
4회차: +130 (누적 345)
6회차: +110 (누적 455)
7회차: +88 (누적 543)
9회차: +140 (누적 683)
10회차: +102 (누적 785)
11회차: +97 (누적 882)
----------------------------------------------
목표 달성! 11회차에서 누적 882개 (목표 800)
유효 8회 / 건너뜀 3회
==============================================
```

### 유의할 점

- **이 문제의 진짜 함정은 `continue` 다.** 인덱스를 늘리는 줄을 `continue` 아래에 두면
  건너뛰는 순간 인덱스가 안 늘어나서 **무한 루프**에 빠짐
  > 인덱스 증가를 `continue` 보다 **위**에 두거나, `continue` 직전에도 증가시켜야 함
- 목표 달성 여부는 플래그 변수(`reached = False`)로 기억해 두면 반복 뒤에 판단하기 편함
- `while` 조건은 `i < len(production)` — 리스트 범위를 넘으면 `IndexError`

### 도전 과제

`TARGET` 을 `2000` 으로 바꿔서 **끝까지 가도 미달**인 경우가 제대로 출력되는지 확인해보기.

## 실습 2. 센서 노이즈 제거와 이동평균

> 리스트 데이터 처리 · 필터링 · 구간 슬라이싱

### 상황

진동 센서가 1분마다 값을 기록했는데 중간에 **터무니없는 값**(센서 오류)이 섞였음.
이걸 걸러내고, 값이 튀는 걸 완만하게 만드는 **이동평균**을 구한 뒤,
평균이 갑자기 크게 변한 구간을 찾아내는 게 목표.

> 이동평균(moving average): 연속한 3개씩 묶어 평균 낸 값들. 값 12개면 이동평균은 10개가 나옴.

```python
raw = [23.1, 24.5, 999.0, 25.2, 24.8, -50.0, 26.1, 27.3, 25.9, 28.4, 26.7, 31.9]
LOW, HIGH = -10.0, 100.0   # 정상 범위 (이 밖은 센서 오류)
WINDOW = 3                 # 이동평균 구간 크기
```

### 요구사항

1. 정상 범위(`LOW` 이상 `HIGH` 이하) 안의 값만 `clean` 리스트에 모으기
2. 범위 밖 값은 `removed` 리스트에 따로 모으고, 제거율을 % 로 출력 (소수 첫째 자리)
3. `clean` 에서 연속 `WINDOW` 개씩 슬라이싱해 평균을 구해 `moving` 리스트 만들기 (소수 둘째 자리 반올림)
4. `moving` 을 번호와 함께 한 줄씩 출력
5. 연속한 이동평균의 **차이(절댓값)** 가 `1.0` 을 넘는 구간을 찾아 `N->N+1 구간 급변 (차이 X)` 형태로 출력
6. `clean` 의 전체 평균, 최댓값, 최솟값 출력 (`sum`/`max`/`min` 사용 가능)

### 써야 하는 개념

`for` / `if` / `.append()` / 슬라이싱 `[i:i+n]` / `range(len(...))` / `sum` `max` `min` `len` / `round` / f-string / 누적

### 예상 출력

```
==============================================
      센서 노이즈 제거와 이동평균
==============================================
원본 12개 / 정상 10개 / 제거 2개
제거된 값: [999.0, -50.0]
제거율: 16.7%
----------------------------------------------
이동평균(3구간) 8개
  1. 24.27
  2. 24.83
  3. 25.37
  4. 26.07
  5. 26.43
  6. 27.2
  7. 27.0
  8. 29.0
----------------------------------------------
급변 구간:
  7->8 구간 급변 (차이 2.0)
----------------------------------------------
정상값 평균: 26.39
최대: 31.9 / 최소: 23.1
==============================================
```

### 유의할 점

- 이동평균 개수는 `len(clean) - WINDOW + 1` 개. `range` 범위를 잘못 잡으면 뒤에서 빈 구간이 생김
- 절댓값 함수(`abs`)를 안 배웠다면 `if` 로 두 방향(`a-b > 1.0` 또는 `b-a > 1.0`)을 다 검사해도 됨
- 부동소수점이라 `round` 를 안 하면 `25.933333333333334` 같은 값이 나옴
- 정상 범위 판정은 `LOW <= v <= HIGH` 연쇄 비교로 한 줄에 쓸 수 있음

### 도전 과제

`WINDOW` 를 `5` 로 바꿔도 코드가 그대로 동작하는지 확인해보기 (숫자를 하드코딩했다면 안 됨).

## 실습 3. 합성진동 기준 설비 랭킹

> 중첩 튜플 · 언패킹 · sorted 정렬 트릭

### 상황

설비마다 진동을 **X축·Y축 두 방향**으로 측정함. 이 둘을 합쳐 `합성진동` 을 구하고,
합성진동이 큰 순서로 줄 세워 위험 설비를 가려내는 게 목표.

합성진동 공식은 피타고라스: `(x**2 + y**2) ** 0.5`

데이터는 `(설비명, (진동X, 진동Y), 전류)` 형태의 **중첩 튜플** 리스트임.

```python
sensors = [
    ("압축기_A", (3.0, 4.0), 62),
    ("펌프_B",   (1.5, 2.0), 71),
    ("송풍기_C", (6.0, 8.0), 55),
    ("절단기_D", (0.9, 1.2), 88),
    ("성형기_E", (5.0, 12.0), 47),
]
# (설비명, (진동X, 진동Y), 전류)
```

### 요구사항

1. `for` 언패킹으로 이름·진동튜플·전류를 꺼내고, 진동튜플을 다시 `x, y` 로 **한 번 더 언패킹**
2. 합성진동을 계산해 `설비명 | X | Y | 합성 | 전류` 형태로 한 줄씩 출력 (합성은 소수 둘째 자리)
3. `(합성진동, 설비명)` 튜플을 리스트에 모으고 `sorted(..., reverse=True)` 로 정렬
4. 정렬 결과를 `N위: 설비명 - 합성진동` 으로 출력
5. 합성진동 `5.0` 이상이면서 전류가 `60` 이상인 설비만 `이중위험` 으로 따로 출력
6. 합성진동 1위 설비의 이름과 값을 콕 집어 출력 (정렬 결과의 0번 활용)

### 써야 하는 개념

중첩 튜플 / 튜플 언패킹(2단계) / `**` 거듭제곱 / `(값, 이름)` 튜플 정렬 트릭 / `sorted(reverse=True)` / `.append()` / `enumerate` / `and` / `round`

### 예상 출력

```
====================================================
         합성진동 기준 설비 랭킹
====================================================
압축기_A | X 3.0 | Y 4.0 | 합성 5.0 | 전류 62A
펌프_B | X 1.5 | Y 2.0 | 합성 2.5 | 전류 71A
송풍기_C | X 6.0 | Y 8.0 | 합성 10.0 | 전류 55A
절단기_D | X 0.9 | Y 1.2 | 합성 1.5 | 전류 88A
성형기_E | X 5.0 | Y 12.0 | 합성 13.0 | 전류 47A
----------------------------------------------------
합성진동 순위:
  1위: 성형기_E - 13.0
  2위: 송풍기_C - 10.0
  3위: 압축기_A - 5.0
  4위: 펌프_B - 2.5
  5위: 절단기_D - 1.5
----------------------------------------------------
최고 진동 설비: 성형기_E (13.0)
이중위험(합성>=5.0 & 전류>=60): ['압축기_A']
====================================================
```

### 유의할 점

- `(합성진동, 설비명)` 처럼 **정렬 기준을 튜플 맨 앞에** 두는 게 핵심.
  `(설비명, 합성진동)` 순서로 담으면 이름(가나다) 기준으로 정렬돼버림
- 중첩 언패킹은 `for name, vib, cur in sensors:` 로 받은 뒤 `x, y = vib` 로 한 번 더 푸는 게 기본.
  `for name, (x, y), cur in sensors:` 처럼 한 번에 풀 수도 있음
- 제곱근은 `** 0.5` (아직 `math` 모듈 안 배웠으니 이걸로)
- 합성진동 값이 딱 떨어지도록 데이터를 만들어 뒀음 — 5.0, 2.5, 10.0, 1.5, 13.0

### 도전 과제

전류까지 포함해 `(합성진동, 전류, 설비명)` 3개짜리 튜플로 정렬해보기. 합성진동이 같을 때 전류로 순위가 갈리는지 확인.

## 실습 4. 3교대 경고 센서 교차 분석

> 셋 · 집합 연산 조합

### 상황

오전 / 오후 / 야간 **세 개 조**가 각각 경고가 뜬 센서를 기록함.
두 개 비교는 해봤으니 이번엔 셋을 동시에 비교해서
"**몇 개 조에서** 경고가 났는가" 로 센서를 분류하는 게 목표.

- 3개 조 전부 → 상시 이상 (설비 자체 문제)
- 정확히 2개 조 → 간헐 이상
- 정확히 1개 조 → 단발 이상

```python
morning   = {"S01", "S02", "S03", "S05", "S08"}
afternoon = {"S02", "S03", "S06", "S08"}
night     = {"S03", "S05", "S07", "S08"}
```

### 요구사항

1. 각 조의 센서 개수와 정렬된 목록 출력
2. 세 조 **전부**에 있는 센서(3중 교집합) 정렬 출력
3. 전체 합집합(경고가 한 번이라도 난 센서) 개수와 정렬 목록 출력
4. **정확히 2개 조**에서만 난 센서 구해서 정렬 출력
5. **정확히 1개 조**에서만 난 센서 구해서 정렬 출력
6. 세 분류의 개수 합이 전체 합집합 개수와 같은지 검산해서 `검산 OK` / `검산 실패` 출력

### 써야 하는 개념

`set` / `&` 교집합 / `|` 합집합 / `-` 차집합 / `sorted()` / `len` / 집합 연산 조합 / f-string

### 예상 출력

```
====================================================
        3교대 경고 센서 교차 분석
====================================================
오전조 5종: ['S01', 'S02', 'S03', 'S05', 'S08']
오후조 4종: ['S02', 'S03', 'S06', 'S08']
야간조 4종: ['S03', 'S05', 'S07', 'S08']
----------------------------------------------------
전체 경고 센서 7종: ['S01', 'S02', 'S03', 'S05', 'S06', 'S07', 'S08']
3개 조 전부(상시 이상): ['S03', 'S08']
정확히 2개 조(간헐 이상): ['S02', 'S05']
정확히 1개 조(단발 이상): ['S01', 'S06', 'S07']
----------------------------------------------------
분류 합계 7종 / 전체 7종
검산 OK
====================================================
```

### 유의할 점

- **정확히 2개 조**가 이 문제의 핵심. 한 번에 되는 연산이 없어서 조합해야 함
  > 두 조씩 교집합을 모두 합친 뒤(`(m&a) | (a&n) | (m&n)`), 거기서 3중 교집합을 빼면 됨
- **정확히 1개 조**는 전체에서 (2개 조 + 3개 조)를 빼면 나옴
- 셋은 순서가 없으니 출력 전에 반드시 `sorted()` — 안 하면 실행할 때마다 순서가 달라 보일 수 있음
- 검산은 `1개 + 2개 + 3개 == 전체` 가 맞는지 보는 것. 분류가 겹치거나 빠지면 여기서 걸림

### 도전 과제

`.union()`, `.intersection()`, `.difference()` 메서드 방식으로도 똑같이 짜보고 결과가 같은지 비교하기.

## 실습 5. 센서 카탈로그 관리 시스템

> 딕셔너리 · get · update · del · items

### 상황

센서 이름을 키로, 측정값을 값으로 하는 딕셔너리를 관리함.
새 측정 묶음이 들어오면 갱신하고, 고장 난 센서는 빼고,
**등록 안 된 센서를 조회해도 프로그램이 죽지 않게** 만드는 게 목표.

```python
sensors = {"모터온도": 78, "진동": 0.5, "펌프압력": 95, "유량": 42}
new_data = {"모터온도": 82, "전류": 61, "진동": 0.8}
broken = "유량"
query_list = ["모터온도", "회전속도", "전류", "습도"]
```

### 요구사항

1. 초기 딕셔너리의 센서 수, 키 목록, 값 목록 출력
2. `update()` 로 `new_data` 를 한 번에 반영하고, **갱신된 키**와 **새로 추가된 키**를 각각 구분해 출력
3. `del` 로 `broken` 센서를 삭제 (단, `in` 으로 존재를 먼저 확인할 것)
4. `query_list` 의 센서를 하나씩 조회 — 있으면 값, 없으면 `미등록` 출력 (`get` 활용)
5. `items()` 로 순회하며 값이 `60` 이상인 센서만 골라 `(값, 이름)` 튜플 리스트에 모으고 내림차순 정렬 출력
6. 전체 값의 합계·평균 출력 (평균은 소수 둘째 자리)

### 써야 하는 개념

`dict` / `[키]` 조회 / `.get(키, 기본값)` / `.update()` / `del` / `in` / `.keys()` `.values()` `.items()` / `len` / `sum` / `sorted` / 튜플 정렬

### 예상 출력

```
==================================================
        센서 카탈로그 관리 시스템
==================================================
등록 센서 4개
키 목록: ['모터온도', '진동', '펌프압력', '유량']
값 목록: [78, 0.5, 95, 42]
--------------------------------------------------
갱신된 센서: ['모터온도', '진동']
추가된 센서: ['전류']
반영 후 5개
--------------------------------------------------
고장 센서 '유량' 삭제 -> 남은 4개
--------------------------------------------------
조회 결과:
  모터온도: 82
  회전속도: 미등록
  전류: 61
  습도: 미등록
--------------------------------------------------
60 이상 센서(내림차순):
  펌프압력 = 95
  모터온도 = 82
  전류 = 61
--------------------------------------------------
합계 238.8 / 평균 59.7
==================================================
```

### 유의할 점

- `update()` 는 **있으면 갱신, 없으면 추가**를 동시에 함. 그래서 반영 **전에** 어떤 키가
  기존에 있었는지 `in` 으로 미리 확인해 둬야 갱신/추가를 구분할 수 있음
  > `update()` 를 먼저 해버리면 구분할 방법이 사라짐 — 순서가 중요
- 없는 키를 `sensors["회전속도"]` 로 꺼내면 `KeyError` 로 프로그램이 죽음. `get` 을 써야 함
- 딕셔너리의 `in` 은 **키**를 봄. 값으로 찾으려 하면 항상 `False`
- `del sensors[키]` 는 없는 키면 에러 — 그래서 `in` 확인이 필요

### 도전 과제

삭제한 `유량` 센서를 다시 추가하고, `get` 의 기본값을 `0` 으로 줘서 미등록 센서까지 합계에 안전하게 포함시켜보기.

## 실습 6. 측정값 대 임계값 초과율 분석

> 두 딕셔너리 연결 · zip · get 기본값

### 상황

측정값 딕셔너리와 임계값 딕셔너리가 **따로** 관리되고 있음.
같은 센서 이름을 다리 삼아 두 딕셔너리를 연결해서, 각 센서가 임계값 대비 몇 % 인지 구하는 게 목표.

문제는 **임계값이 등록 안 된 센서**가 섞여 있다는 것. 이걸 `get` 으로 안전하게 처리해야 함.
추가로, 이름 리스트와 값 리스트를 `zip` 으로 묶어 딕셔너리를 만드는 것도 연습함.

```python
names  = ["모터온도", "진동", "펌프압력", "전류", "유량"]
values = [95, 0.8, 88, 61, 47]

limits = {"모터온도": 90, "진동": 1.0, "펌프압력": 90, "전류": 50}
# 주의: "유량" 임계값이 없음
```

### 요구사항

1. `zip` 으로 `names` 와 `values` 를 묶어 `measured` 딕셔너리 만들기
2. `items()` 로 순회하며 각 센서의 임계값을 `get` 으로 조회 — **없으면 건너뛰고** `임계값 미등록` 출력
3. 초과율(`측정값 / 임계값 * 100`)을 소수 첫째 자리까지 구해 `센서명: 측정 X / 임계 Y -> Z%` 출력
4. 초과율이 100 을 넘으면 `초과`, 90 이상이면 `임박`, 아니면 `정상` 판정을 같은 줄에 붙이기
5. `초과` 판정 센서 이름만 모아 정렬 출력, 없으면 `초과 없음`
6. 임계값이 등록된 센서들의 **평균 초과율** 출력 (소수 둘째 자리)

### 써야 하는 개념

`zip` / `dict()` / `.items()` / `.get()` / `None` 판정 / `if-elif-else` / `.append()` / `sorted` / `sum` / `len` / `round`

### 예상 출력

```
========================================================
        측정값 대 임계값 초과율 분석
========================================================
측정 딕셔너리 5개: {'모터온도': 95, '진동': 0.8, '펌프압력': 88, '전류': 61, '유량': 47}
--------------------------------------------------------
모터온도: 측정 95 / 임계 90 -> 105.6% [초과]
진동: 측정 0.8 / 임계 1.0 -> 80.0% [정상]
펌프압력: 측정 88 / 임계 90 -> 97.8% [임박]
전류: 측정 61 / 임계 50 -> 122.0% [초과]
유량: 임계값 미등록 -> 판정 불가
--------------------------------------------------------
초과 센서: ['모터온도', '전류']
판정 대상 4개 / 평균 초과율 101.33%
========================================================
```

### 유의할 점

- `dict(zip(names, values))` 가 두 리스트를 딕셔너리로 만드는 표준 패턴.
  두 리스트 **순서가 어긋나면** 엉뚱한 이름에 엉뚱한 값이 붙으니 개수부터 확인
- `limits.get("유량")` 은 `None` 을 돌려줌. `None` 인지 검사해서 건너뛰어야 함
  > 여기서 `limits.get("유량", 0)` 처럼 기본값 `0` 을 주면 **0으로 나누기 에러**가 나니 주의
- 판정 순서 주의: `100 초과` 를 먼저 걸러야 함. `90 이상` 을 위에 두면 초과까지 전부 임박으로 빠짐
- 평균 초과율은 **임계값이 있는 센서만** 세야 함 (전체 개수로 나누면 틀림)

### 도전 과제

임계값이 없는 센서를 위해 `기본 임계값 = 100` 을 정해 두고, `get(name, 100)` 으로 처리해 전부 판정해보기.

## 실습 7. 설비별 측정 이력 관리

> 중첩 딕셔너리 · 값에 리스트 담기

### 상황

설비 이름을 키로 하고, 값에 **또 딕셔너리**를 담아 설비 정보를 관리함.
그 안쪽 딕셔너리의 `이력` 키에는 **리스트**가 들어 있음 (여러 번 측정한 기록).

`딕셔너리 -> 딕셔너리 -> 리스트` 3층 구조를 뚫고 들어가 통계를 내는 게 목표.

```python
plant = {
    "1번모터": {"상태": "정상", "이력": [78, 79, 81, 80]},
    "2번펌프": {"상태": "경고", "이력": [92, 95, 97, 99, 101]},
    "3번팬":   {"상태": "정상", "이력": [55, 54, 56]},
    "4번압축기": {"상태": "경고", "이력": [88, 91]},
}
```

### 요구사항

1. `items()` 로 순회하며 설비마다 `설비명 [상태] 측정 N회` 출력
2. 각 설비의 이력 평균·최대·최소를 구해 같은 블록에 출력 (평균은 소수 둘째 자리)
3. 이력의 **마지막 값 - 첫 값** 으로 추세를 구해 `상승`/`하락`/`유지` 판정 출력
4. 상태가 `경고` 인 설비 이름만 모아 정렬 출력
5. **모든 설비의 모든 측정값**을 하나의 리스트로 합쳐 전체 평균과 총 측정 횟수 출력
6. 평균이 가장 높은 설비를 찾아 `최고 평균 설비: 이름 (값)` 출력 (`(평균, 이름)` 튜플 정렬 활용)
7. 대괄호를 연달아 써서 `2번펌프` 의 이력 **첫 값**과 **마지막 값**을 직접 꺼내 출력 (`plant[설비][항목][번호]`)
8. `5번밸브` 가 등록돼 있는지 `not in` 으로 확인해 `미등록 설비` 출력

### 써야 하는 개념

중첩 딕셔너리 / `plant[설비][항목]` / 값에 리스트 / `.items()` / `sum` `max` `min` `len` / `.extend()` 또는 `.append()` / 튜플 정렬 / `round` / `if-elif-else`

### 예상 출력

```
======================================================
          설비별 측정 이력 관리
======================================================
1번모터 [정상] 측정 4회
   이력: [78, 79, 81, 80]
   평균 79.5 / 최대 81 / 최소 78
   추세: 상승 (+2)
2번펌프 [경고] 측정 5회
   이력: [92, 95, 97, 99, 101]
   평균 96.8 / 최대 101 / 최소 92
   추세: 상승 (+9)
3번팬 [정상] 측정 3회
   이력: [55, 54, 56]
   평균 55.0 / 최대 56 / 최소 54
   추세: 상승 (+1)
4번압축기 [경고] 측정 2회
   이력: [88, 91]
   평균 89.5 / 최대 91 / 최소 88
   추세: 상승 (+3)
------------------------------------------------------
경고 설비: ['2번펌프', '4번압축기']
전체 측정 14회 / 전체 평균 81.86
최고 평균 설비: 2번펌프 (96.8)
------------------------------------------------------
2번펌프 이력 첫 값: 92
2번펌프 이력 끝 값: 101
5번밸브: 미등록 설비
======================================================
```

### 유의할 점

- 안쪽 값을 꺼낼 때 대괄호를 두 번 씀: `plant["2번펌프"]["이력"]` -> 리스트
  거기에 인덱스를 한 번 더 붙이면 값 하나: `plant["2번펌프"]["이력"][0]`
- 전체 측정값을 합칠 땐 `.extend()` 가 편함. `.append()` 를 쓰면 리스트 안에 리스트가 들어감
  > `all_values.extend(history)` vs `all_values.append(history)` — 결과가 완전히 다름
- 추세는 `이력[-1] - 이력[0]` 으로 구함. 0이면 `유지`
- 최고 평균 설비는 `(평균, 이름)` 튜플을 모아 `sorted(reverse=True)` 후 0번을 꺼내면 됨

### 도전 과제

각 설비의 이력에서 **직전 값보다 오른 횟수**를 세어 `연속 상승 N회` 를 출력해보기.

## 실습 8. 센서 통계 함수 세트 만들기

> 함수 정의 · 매개변수 · 반환값 · 여러 값 반환

### 상황

지금까지 매번 손으로 짜던 통계 계산을 **함수로 묶는 게** 목표.
한 번 만들어 두면 어떤 센서 데이터에도 그대로 쓸 수 있어야 함.

핵심은 `print` 가 아니라 **`return` 으로 값을 돌려주는 것**.
돌려받은 값을 다른 함수에 넘겨 사슬처럼 이어 쓰는 것까지 해봄.

```python
line_a = [78, 85, 92, 66, 88, 74]
line_b = [95, 97, 99, 101]
line_c = []          # 빈 리스트 - 이것도 처리돼야 함
```

### 요구사항

1. `get_average(values)` — 평균을 **return**. 빈 리스트면 `0` 을 돌려줄 것 (0으로 나누기 방지)
2. `get_min_max(values)` — 최솟값과 최댓값 **두 개를 한 번에 return** (튜플로 묶여 나감)
3. `count_over(values, limit)` — `limit` 초과 개수를 return
4. `judge(avg)` — 평균을 받아 `위험`(90 이상) / `주의`(80 이상) / `정상` 문자열을 return
5. 세 라인 각각에 대해 위 함수들을 호출하고, `get_min_max` 는 **언패킹으로 두 변수에 받기**
6. `get_average` 의 반환값을 변수에 담아 `judge` 에 넘기는 **함수 조합**으로 최종 판정 출력
7. 각 함수에 한 줄짜리 docstring 달기

### 써야 하는 개념

`def` / 매개변수 / `return` / 여러 값 반환(튜플) / 반환값 언패킹 / 함수 조합 / docstring / 빈 리스트 방어 / `sum` `min` `max` `len`

### 예상 출력

```
====================================================
         센서 통계 함수 세트
====================================================
[A라인] 측정 6회
   평균 80.5 / 최소 66 / 최대 92
   90 초과 1개 -> 판정: 주의
[B라인] 측정 4회
   평균 98.0 / 최소 95 / 최대 101
   90 초과 4개 -> 판정: 위험
[C라인] 측정 0회
   평균 0 / 최소 0 / 최대 0
   90 초과 0개 -> 판정: 정상
====================================================
```

### 유의할 점

- **`print` 와 `return` 을 헷갈리지 말 것.** `print` 만 하면 값이 화면에 보일 뿐
  다른 계산에 쓸 수 없음. 이 문제는 전부 `return` 이어야 함
- 빈 리스트 `line_c` 가 함정. `sum([]) / len([])` 은 `ZeroDivisionError`
  > 함수 맨 위에서 `if len(values) == 0: return 0` 으로 먼저 막는 게 정석 (early return)
- `get_min_max` 는 빈 리스트면 `min()`/`max()` 자체가 에러남. 이것도 막아야 함 -> `(0, 0)` 반환
- `low, high = get_min_max(line_a)` 처럼 **변수 개수와 반환 개수가 같아야** 언패킹됨
- `return` 을 만나면 함수가 **즉시 끝남**. `return` 아래 코드는 실행 안 됨

### 도전 과제

`judge` 에 기본값 인자를 추가해서 (`judge(avg, danger=90, warn=80)`) 기준선을 호출할 때 바꿀 수 있게 만들어보기.

## 실습 9. 유연한 설비 판정 함수

> 기본값 인자 · 키워드 인자 · 지역변수

### 상황

설비마다 임계 기준이 다름. 그런데 대부분은 **표준 기준**을 쓰고 가끔만 다른 값을 씀.
그래서 기준을 **기본값 인자**로 미리 정해 두고, 필요할 때만 덮어쓰는 함수를 만드는 게 목표.

덤으로 **지역변수**가 함수 밖으로 새어 나가지 않는다는 것도 직접 확인해봄.

```python
records = [
    ("압축기_A", 88, {}),
    ("펌프_B",   95, {}),
    ("송풍기_C", 88, {"danger": 85}),
    ("절단기_D", 79, {"warn": 75, "unit": "bar"}),
]
# (설비명, 측정값, 덮어쓸 기준)
```

### 요구사항

1. `check(name, value, danger=90, warn=80, unit="도")` 함수 정의 — 뒤 세 개가 기본값 인자
2. 함수 안에서 판정 결과와 판정 근거 문자열을 만들어 **두 값을 튜플로 return**
3. `records` 를 순회하며, 덮어쓸 기준이 **비어 있으면 기본값으로**, 있으면 **키워드 인자로 덮어써서** 호출
4. 반환값을 언패킹으로 받아 `설비명: 값단위 -> 판정 (근거)` 형태로 출력
5. 같은 측정값 `88` 인데 `압축기_A` 와 `송풍기_C` 의 판정이 다른 이유를 주석으로 적기
6. 함수 안에서 만든 지역변수를 함수 밖에서 출력하면 어떻게 되는지 주석으로 적기 (실제로 실행하진 말 것)

### 써야 하는 개념

`def` / 기본값 인자 / 키워드 인자 / 필수 인자가 앞·기본값이 뒤 규칙 / 여러 값 반환 / 언패킹 / 지역변수 / `dict.get()` / f-string

### 예상 출력

```
==========================================================
           유연한 설비 판정 함수
==========================================================
압축기_A: 88도 -> 주의 (88 >= 주의기준 80)
펌프_B: 95도 -> 위험 (95 >= 위험기준 90)
송풍기_C: 88도 -> 위험 (88 >= 위험기준 85)
절단기_D: 79bar -> 주의 (79 >= 주의기준 75)
----------------------------------------------------------
같은 88인데 판정이 다른 이유: danger 기본값 90 vs 덮어쓴 85
지역변수는 return 으로 내보내야만 밖에서 쓸 수 있음
==========================================================
```

### 유의할 점

- **기본값 인자 순서 규칙**: 기본값 없는 매개변수가 앞, 있는 게 뒤.
  `def check(danger=90, name, value)` 는 **정의하는 순간** 에러
- 덮어쓸 기준이 딕셔너리로 들어오니 `opt.get("danger", 90)` 처럼 꺼내서
  키워드 인자로 넘기면 깔끔함 — `check(name, value, danger=..., warn=...)`
- `송풍기_C` 는 `danger` 를 85로 낮췄으니 88이 위험으로 판정됨.
  같은 값이라도 **기준이 바뀌면 결과가 바뀐다**는 게 이 문제의 핵심
- 지역변수는 함수가 끝나면 사라짐. 밖에서 쓰려면 반드시 `return` 으로 내보내야 함

### 도전 과제

`unit` 기본값을 활용해 압력 설비만 `bar`, 나머지는 `도` 로 나오게 하고, `unit` 만 키워드로 콕 집어 바꿔보기.

## 실습 10. 스마트 정비 통합 리포트 (종합)

> 함수 + 딕셔너리 + 셋 + 튜플 + while + 리스트 처리 전부

### 상황

마지막 문제. 지금까지 배운 걸 **전부** 한 프로그램에 넣음.

여러 설비의 측정 이력을 받아 정제하고, 통계를 내고, 위험 설비를 가려내고,
어제 기록과 비교해 새로 생긴 이상을 찾고, 최종 리포트를 출력하는 미니 시스템.

> 한 번에 다 짜려 하지 말고 함수 하나씩 만들어 붙일 것.

```python
plant = {
    "압축기_A": [78, 85, 999, 88, 82],
    "펌프_B":   [95, 97, 99, 101, 98],
    "송풍기_C": [55, 54, -20, 56, 58],
    "절단기_D": [88, 91, 89, 90, 92],
    "성형기_E": [70, 68, 72, 71, 69],
}
yesterday_alerts = {"펌프_B", "성형기_E"}
VALID_LOW, VALID_HIGH = 0, 200
DANGER = 90
```

### 요구사항

1. `clean_values(values, low, high)` — 범위 밖 값을 제거한 **새 리스트**를 return
2. `get_stats(values)` — `(평균, 최소, 최대)` **세 값을 한 번에** return, 빈 리스트면 `(0, 0, 0)`
3. `judge(avg, danger=90)` — 기본값 인자를 쓴 판정 함수, `위험`/`정상` return
4. 각 설비를 순회하며 정제 -> 통계 -> 판정하고, 제거된 이상치 개수도 함께 출력
5. 평균이 `DANGER` 이상인 설비를 `today_alerts` **셋**에 모으기
6. 셋 연산으로 `신규 이상`(오늘만), `지속 이상`(양쪽), `해소`(어제만) 각각 정렬 출력
7. `(평균, 설비명)` 튜플 리스트로 평균 순위를 만들어 `while` 로 **상위 3개만** 출력
8. 전체 설비 수·정상 수·위험 수와 위험 비율(%)을 f-string 으로 요약 출력

### 써야 하는 개념

`def` / 매개변수 / 기본값 인자 / 여러 값 반환 / 언패킹 / 딕셔너리 순회 / `set` 집합연산 / 튜플 정렬 / `while` / `break` / 리스트 필터링 / `sum` `min` `max` `len` `round` `sorted`

### 예상 출력

```
==========================================================
          스마트 정비 통합 리포트
==========================================================
압축기_A
   원본 5개 / 정제 4개 (이상치 1개 제거)
   평균 83.25 / 최소 78 / 최대 88 -> 정상
펌프_B
   원본 5개 / 정제 5개 (이상치 0개 제거)
   평균 98.0 / 최소 95 / 최대 101 -> 위험
송풍기_C
   원본 5개 / 정제 4개 (이상치 1개 제거)
   평균 55.75 / 최소 54 / 최대 58 -> 정상
절단기_D
   원본 5개 / 정제 5개 (이상치 0개 제거)
   평균 90.0 / 최소 88 / 최대 92 -> 위험
성형기_E
   원본 5개 / 정제 5개 (이상치 0개 제거)
   평균 70.0 / 최소 68 / 최대 72 -> 정상
----------------------------------------------------------
오늘 이상 설비: ['절단기_D', '펌프_B']
어제 이상 설비: ['성형기_E', '펌프_B']
  신규 이상: ['절단기_D']
  지속 이상: ['펌프_B']
  해소된 설비: ['성형기_E']
----------------------------------------------------------
평균 상위 3개:
  1위: 펌프_B - 98.0
  2위: 절단기_D - 90.0
  3위: 압축기_A - 83.25
----------------------------------------------------------
전체 5대 / 정상 3대 / 위험 2대
위험 비율: 40.0%
==========================================================
```

### 유의할 점

- 함수 3개를 **먼저** 만들고 그 다음에 순회 코드를 짜는 게 편함.
  함수가 없으면 순회 코드 안이 순식간에 지저분해짐
- `while` 로 상위 3개 뽑을 때 **설비가 3개 미만일 수도** 있다고 가정하고
  `i < 3 and i < len(ranking)` 처럼 두 조건을 다 걸어야 안전함
- 이상치 제거 후 리스트가 비면 통계 함수가 터짐 -> `(0, 0, 0)` 반환으로 막아둘 것
- 셋 연산 방향 주의: `today - yesterday` 는 신규, `yesterday - today` 는 해소. 반대로 쓰면 결과가 뒤집힘
- 원본 `plant` 를 직접 수정하지 말고 정제 결과를 **새 리스트**로 받을 것

### 도전 과제

정제 후 값이 하나도 안 남은 설비가 있으면 `데이터 없음` 으로 따로 표시하고 통계에서 제외해보기.
